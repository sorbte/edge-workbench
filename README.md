# Microsoft Edge 持久化浏览器工作台

这是一个使用 **Playwright + Tkinter** 编写的可视化浏览器控制程序。它直接驱动本机安装的 Microsoft Edge，不会改动你日常使用的 Edge 配置，而是把模拟浏览产生的内容保存在项目内的独立目录：

- `edge_profile/`：Edge 用户资料目录，持久保存 Cookies、LocalStorage、Session Storage、IndexedDB、Service Worker、HTTP 磁盘缓存、历史记录、偏好设置等。
- `downloads/`：浏览器下载目录。
- `runtime/operations.jsonl`：页面导航与模拟操作日志。
- `runtime/state_snapshots/`：手动保存的状态摘要快照（只记录 Cookie 元数据，不记录 Cookie 值）。

## 运行

双击 `run.bat`，或者执行：

```powershell
py -3.12 -m pip install -r requirements.txt
py -3.12 edge_workbench.py --autostart
```

程序启动后会自动打开 Edge 和 `https://cn.bing.com/`。

## 项目结构

实现按职责拆分在 `workbench/` 包内，根目录的 `edge_workbench.py` 只保留启动入口：

| 模块 | 职责 |
|---|---|
| `workbench/config.py` | 路径、外观常量、任务参数、设置读写与工具函数 |
| `workbench/spider_scripts.py` | 宠物（蜘蛛）页面注入脚本：顶层特效引擎 + iframe 词采器 |
| `workbench/page_scripts.py` | Rewards / 账户等页面数据提取脚本 |
| `workbench/worker.py` | Playwright 浏览器工作线程（导航、搜索、任务、宠物联动） |
| `workbench/ai_manager.py` | Agent（模型接入 + 系统提示词 + 内置工具）管理与统一调用口 `run_agent`（DeepSeek 等平台预设、工具循环、SSRF 边界校验） |
| `workbench/plugin_runtime.py` | 插件子进程入口、进程代理、插件基类与插件管理器 |
| `workbench/app.py` | CustomTkinter 桌面 UI 与 `main()` |

插件依旧通过 `from edge_workbench import ...` 复用宿主常量与基类（`workbench` 包已把自身
注册为 `edge_workbench` 别名，主进程与插件子进程都适用）；旧的启动命令不变，
也支持 `py -3.12 -m workbench` 启动。

## 界面设计

- 无 Windows 原生标题栏，使用自定义无边框窗口
- 自定义拖动标题栏、最小化、最大化 / 还原、关闭按钮
- 右下角拖动缩放
- Codex 风格布局：标题栏与侧栏同为米灰色无缝衔接，内容区为整体浮起的白色圆角卡片（左侧与顶部带渐变软阴影）
- 侧边导航：纯导航列表，导航项由「已安装插件页面 + 核心页面」组成（默认：学习通助手、微软积分助手、总览、宠物、Agent 管理、运行日志），选中项为贴左全宽白色高亮条；底部显示快捷键提示
- 功能插件化：功能页以插件形式放在 `plugins/` 目录，安装（放入目录）即出现在左侧菜单，禁用/卸载后自动消失；详见下方「插件系统」
- 默认进入第一个插件页；Alt+1…N 按侧栏顺序切换页面
- 一键自动运行 = 完整自动化流程：启动 Edge（如未运行）→ 获取基本数据 → 搜索任务 → 触发每日任务 → 最终数据同步；入口在积分助手页页头最左侧的「▶ 启动」按钮，运行中按钮禁用，可在积分助手页取消任务
- 隐藏模式：总览页标题栏「显示器」图标按钮开启后（按钮变为黑色激活态，悬停显示说明），浏览器以无头方式在后台运行，自动化照常执行；浏览器运行中点击切换会自动取消任务并重启浏览器，新模式立即生效（浏览器未运行时仅记录设置，下次启动生效），注意事项：无头浏览器更易被网站反自动化策略识别，Rewards 积分存在不计入的风险
- 防重复点击：所有长耗时操作的按钮在执行期间自动禁用，worker 命令完成后自动恢复；任务运行时「开始」按钮禁用、对应「取消任务」按钮才可用；一键自动化运行期间手动任务按钮整体联动禁用
- 总览页布局：命令条式地址栏（等宽字体 + 回车执行）+「打开页面」+「必应搜索」+ 新建标签页图标；标题「运行总览」行右侧为一组图标按钮——启动 ▶ / 重启 ⟳ / 隐藏切换 ⌷ / 停止 ■（红色，均为 Segoe MDL2 图标，悬停显示中文名称）；「TELEMETRY / 运行指标」行右侧为刷新 ↻ / 快照 / 清理缓存 / 资料目录四枚图标；底部等宽路径提示行；原 ACTIONS 卡片取消
- 必应搜索：总览页输入框的内容会打开 `cn.bing.com` 后逐字输入搜索框并回车；输入框为空时仅打开必应首页
- 任务保护：搜索任务 / 一键自动化 / 模拟真实浏览 / 获取数据等运行期间，「清理缓存」与「清理 Rewards 缓存」会被拒绝并写入日志提示，不会中断正在运行的任务；「停止浏览器」与「重启浏览器」是显式的中断入口（重启会先取消任务、再按当前窗口模式启动）
- 清理缓存完成或停止浏览器后，日志会提示可点击「启动浏览器」继续；隐藏/显示切换在浏览器运行中时会自动重启浏览器立即生效（「重启浏览器」为手动入口，同样先取消任务再按当前窗口模式重启）
- 微软积分助手页（插件）：未登录 / 无法识别数据时显示居中空状态页（原因说明 + 「获取基本数据」引导按钮），登录并获取成功后切换到数据卡片；页头标题行右侧为整页唯一一组图标按钮（刷新全部数据 ↻ / 清理 Rewards 缓存 🗑 / 打开数据 JSON / 测试点击，悬停显示中文名）；下方依次为「ACCOUNT 账户与数据摘要」卡（账户信息 + Rewards 数据摘要，两页原有内容已去重合并）、搜索任务 / 每日任务两张独立进度卡（各自的进度条、开始与取消按钮）、「SEARCH RULES 积分规则」网格
- 学习通助手页（插件）：页头排版与微软积分助手一致——标题行带独立进程运行状态（未启动 / 启动中 / 运行中 / 就绪 / 等待登录 / 已完成 / 取消中 / 已取消 / 异常），进程行左侧显示「进程: PID」和可点击的「资料」按钮（打开插件专用 Edge 资料目录）、右侧为运行详情；操作行左侧仅保留「打开个人空间」，右侧图标按钮为刷新全部数据 ↻ / 清理本地缓存 / 打开缓存 JSON / 切换独立 Edge 窗口显示（独立 Edge 运行中切换会自动重启使其立即生效；无全局任务进度条）。打开页面时只读取本机缓存，不会自动启动独立 Edge；未获取数据时空状态页显示「获取基本数据」引导按钮（已有数据后右上角图标变为「刷新全部数据」）。「ACCOUNT / 用户与在读课程」单张卡片合并用户信息（用户名、用户 ID、平台与缓存说明，无头像）与在读课程统计（在读课程 / 已完成 / 未完成 / 平均进度）；课程列表显示课程类型、学期、完成状态徽章、任务点、测验、待完成数量和整体进度（未完成课程排在前、按进度升序）。「开始学习」「取消任务」下沉到在读课程卡片内按课程发起（已完成的课程只保留「回顾课程」），同一账号同一时间只允许一个任务，避免同时播放触发验证码；标题行右侧图标按钮组为：刷新全部数据 ↻ / 清理本地缓存 / 批改作业开关（铅笔图标，高亮=开启页面批改菜单，与任务互不冲突） / 打开缓存 JSON / 切换独立 Edge 窗口显示 / 学习通设置（齿轮，在页面内切换到设置视图，顶部「← 返回」可回到主视图）。首次使用会跳转到学习通登录页，请在插件独立 Edge 中使用“学习通”App 扫描二维码登录；用户与课程缓存写入 `runtime/plugins/chaoxing_assistant/profile.json` 和 `courses.json`，Cookie/LocalStorage/SessionStorage 快照写入 `auth_state.json`。开启「操作可视化」后，同步与自动学习全程带宠物联动漫游特效（可在「宠物」页管理）。
- 学习通助手「开始学习」（课程卡片内）：只有用户点击后才执行，只处理该门课程；它会从课程目录查找未完成章节，按视频、PPT/PDF、电子书分别完成，并在每个任务点后重新检查。连续 3 次仍有任务点未完成时，点击下一节并在界面提示“课程异常”；处理报告写入 `runtime/plugins/chaoxing_assistant/study_report.json`。
- 学习通助手「批改作业」（工具栏铅笔图标开关 + 页面右上角「AI 批改助手」菜单，依赖「Agent 管理」页的 Agent，已完成课程同样可用）：开关高亮后，仅作业 / 章节测验类页面（含 iframe 内嵌测验）右上角注入批改菜单，其他页面不显示；菜单可按住标题栏拖动到任意位置，单击标题折叠 / 展开，新开的测验页面自动出现。打开作业 / 章节测验页面点「开始批改」，AI 提取当前页面的题目（当前支持单选、多选、判断、填空、简答；阅读理解/完形填空按小题逐题作答，材料自动关联到每道小题）并逐题解答：菜单实时显示「逐题作答 N/M」进度，单题漏答自动补答（不确定也给最佳猜测）。批改结果只以批注形式插在每道题（小题）下方：「AI 参考答案」、一句话解释和「你的答案」状态——已作答标注与 AI 一致/不一致，未作答明确写「你的答案：未作答」并以橙色批注醒目标出；已批阅的旧测验同样可批注（温故知新）。不自动选择、不自动填写、绝不提交；「重新批改」覆盖上一轮批注，「停止」中断当前页；批改中关闭或跳转页面会安全中断本页，打开新的测验页面即可继续。批改不占用任务闸门：与「开始学习」「刷新全部数据」互不影响（任务运行期间菜单不刷新、批改不响应，任务结束后自动恢复）。批改 Agent 在本页「学习通设置」视图选择（工具栏齿轮按钮进入，顶部「← 返回」回主视图；写入 runtime/plugins/chaoxing_assistant/ai_settings.json，开关状态同存于此）；批改记录追加写入 ai_homework_report.json。答案输出由 LangChain 结构化输出强制固定格式（langchain-openai，requirements.txt 已锁定；未安装或失败时自动降级为接口级 JSON 模式与文本兜底解析），保证每道题都有带解释的参考答案。

- 合并去重说明：原「Rewards」页与「账户与规则」页的空状态、获取数据入口、清理缓存入口、可用积分（与账户积分重复）、积分规则文本摘要（与规则网格重复）均已合并为一份
- 搜索任务与每日任务的事件流相互独立（flow 标记），互不覆盖对方进度
- 小字号统一调大（等宽 10pt 起、正文 11pt 起），日志终端面板 10pt
- 运行日志页：深色终端面板（`▌ operations` 头行、弱色时间戳、按级别着色的日志）
- 快捷键：Alt+1…5 切换页面
- 整体主按钮为石墨黑，避免高饱和蓝色
- Edge 路径自动检测：依次检查 Program Files、Program Files (x86) 和 LocalAppData，并使用 Playwright channel=msedge 驱动本机 Edge

## 插件系统

功能页面以插件形式与宿主解耦：宿主只保留总览、运行日志等核心页，其余功能装进 `plugins/` 下的独立目录。

- 插件如需与宠物联动特效配合（指向性抓取、冲刺互动、庆祝等），接口文档见 [docs/spider-api.md](docs/spider-api.md)
- 插件如需接入 AI（多平台配置、提示词技能、对话调用与 SSRF 边界），接口文档见 [docs/ai-api.md](docs/ai-api.md)
- 目录结构：每个插件一个文件夹，含 `manifest.json`（清单）与入口模块（默认 `plugin.py`）

  ```json
  {
    "id": "microsoft_points_assistant",
    "name": "微软积分助手",
    "version": "1.0.0",
    "description": "Microsoft Rewards 积分数据、账户规则与任务中心",
    "entry": "plugin.py",
    "plugin_class": "MicrosoftPointsAssistantPlugin"
  }
  ```

- 安装即显示：把插件文件夹放进 `plugins/` 后启动程序，页面会自动注册到左侧菜单顶部；删除文件夹或禁用后消失
- 热更新（无需重启）：插件管理页点「扫描新插件」即可装载新放入 `plugins/` 的插件；开关切换即时挂载/卸载页面；关闭再打开开关会重新读取插件代码（改完插件代码即时生效）；文件夹被删除后再扫描会自动卸载
- 插件管理界面：核心页「插件管理」（侧栏最后一项）列出全部已安装插件（名称、id、版本、描述、加载状态），每项一个启用/禁用开关，页头提供扫描新插件 / 重启程序 / 打开插件目录三个图标
- 任务保护：插件的自动化任务运行中，该插件不能被停用（提示后自动弹回开关）
- 插件加载失败（清单损坏、入口缺失等）会在管理页以红色标注原因；`plugins/` 为空时显示安装指引
- 启用 / 禁用：在 `runtime/plugins.json` 写入 `{"disabled": ["插件id"]}`（文件不存在时全部启用）
- 插件类继承宿主的 `WorkbenchPlugin` 基类：实现 `build_pages(parent)` 返回页面（页键、侧栏标题、框架），通过 `handle_event(event)` 接收 worker 事件流（rewards_data / rewards_account / account_info_status / search_task_status / auto_status），并可复用宿主的卡片、按钮、图标按钮、日志等 UI 套件
- 需要独立浏览器的插件可在 `manifest.json` 中增加 `worker_entry`；宿主会将插件命令交给该 worker 注册，学习通助手使用 `chaoxing_start`（仅启动独立 Edge）/ `chaoxing_refresh` / `chaoxing_open_space` / `chaoxing_open_course` / `chaoxing_study` / `chaoxing_ai_menu`（页面批改菜单开关）六条命令。
- 单个插件加载或运行失败只写入运行日志，不影响宿主启动和其他插件

## 可视化功能

- 启动 / 停止 / 重启 Microsoft Edge（总览页标题行图标）
- **宠物（操作可视化联动特效，纯视觉）**：「宠物」页（左侧菜单）统一管理。当前上架的宠物是**蜘蛛**（8 条腿 IK 步态、深色描边白芯配色，深浅页面都清晰），宠物框架已参数化（造型/配色/速度），后续在 `PETS` 注册表里加一项即可上架新宠物。总览页标题行的“眼睛”图标与宠物页开关同步。它唯一的页面内控件是右下角的宠物徽标（互动入口，见下），无 HUD/状态控制台/进度条/Cookie 卡片，不改动页面 DOM（词条高亮走 CSS Custom Highlight API），从不代替页面滚动，除徽标与菜单外整体 `pointer-events:none` 不拦截任何点击。**抓取是“指向性接触采集”：只在插件要获取信息的时刻显式触发**——小目标宠物直接冲刺过去、抵达后原地采集；大块数据（如整个搜索结果列表）则走**巡回采集**：宠物沿弓字形路线在目标区域内巡游，爬到谁身上就点亮谁（词条随爬行逐个标记，而不是一抵达整块闪亮），走完全程后再以波纹节奏把剩余词条（含视口外、滚动后可见的部分）补齐；平时随机游走、路过不抓取，点击页面时宠物会冲刺过去互动（同样不抓取）。
  - **多帧词采（覆盖 iframe）**：顶层文档之外，worker 会把「词采器」懒注入到页面全部子帧（经 Playwright/CDP，**跨域 iframe 同样生效**），并把主视口矩形换算成帧内坐标逐帧采集；`fetch/harvest` 返回的采集数是顶层 + 全部帧的合计，`spider_fetch_text` 在顶层找不到文本时会继续到各帧里查找。
  - 宠物页功能：宠物卡片（应用/使用中，切换后立即重新注入已打开的标签页）、主开关（与总览页“眼睛”同步）、互动按钮（召唤到页面中央 / 开心庆祝 / 撒一把粒子）。互动入口主要在**浏览器页面里**：每个注入了宠物的标签页右下角有一枚宠物徽标，点开菜单即可召唤 / 庆祝 / 撒粒子（Esc 或点击空白处收起，菜单动作与工作台按钮完全一致）；工作台按钮保留，便于浏览器在后台 / 无头模式时使用。
  - 页面内公开 API（`window.__wbs`，坐标为视口坐标）：`fetchRect(x,y,w,h)` / `fetchAt(x,y,r)` 指向性抓取、`dashTo(x,y)` 纯冲刺、`harvestRect/harvestAt` 原地立即采集（顶层词条）、`burst/ring` 粒子与涟漪、`celebrate()` 转圈庆祝、`wander()` 换目标、`addCollected(n)` 帧采集记账、`state()` 状态（含 `fetching` 字段）、`rewordify()` 重扫词条、`destroy()` 移除。同一宠物重复注入只重扫词条（DOM 未变化时完全无副作用、保留采集统计），换宠物则销毁重建，页面跳转后自动全新初始化；各帧内另有轻量词采器 `window.__wbs_collector`（只扫描/高亮/计数，不做动画）。
  - Worker 侧公共方法（插件代码直接调用，特效关闭时自动静默跳过）：`worker.spider_fetch_element(page, element=定位器 或 selector= 或 box=)`、`worker.spider_fetch_text(page, r"积分|points")`（按文本自动定位信息元素，含 iframe 内文本）、`worker.spider_dash_to(...)`、`worker.spider_harvest_element / spider_harvest_point / spider_burst / spider_ring / spider_celebrate / spider_wander`；移动类接口带 `wait` 参数（`fetch_*` 默认 `"auto"` 按冲刺距离自动等待宠物抵达，500~2600ms；大块数据的巡回采集会等到整条路线巡游并补齐完毕（约 3.4s 量级，最多补等 4.2s）；`dash_to` 默认不等待，可传毫秒做"抢先冲刺"）。
  - 内置联动点：Rewards 获取信息（宠物按文本爬到积分数字上接触采集，读取前稍作停顿）、必应搜索与搜索任务的新闻结果页（宠物爬到结果区采集）、每日任务点击（pointerdown 自动冲刺）、Rewards 数据获取完成（庆祝）。主框架每次导航后自动注入（长任务里直接 `page.goto` 的页面也能跟上）。
  - 设置写入 `runtime/workbench.json`，重启后保持；主工作台与插件进程的 Edge 都生效，`chrome://` 等内部页自动跳过。
  - **插件联动接口文档：[docs/spider-api.md](docs/spider-api.md)**（Worker 侧方法、页面内 `window.__wbs` API、时序建议与完整示例）

## 持久化说明

Edge 资料由 Playwright 的 `launch_persistent_context(user_data_dir=...)` 管理。关闭程序后再次启动会继续使用同一份资料，因此登录状态、Cookie、站点缓存和历史记录都会保留。

注意：`edge_profile/` 属于敏感数据目录，不要提交到 Git，也不要随意分享。
